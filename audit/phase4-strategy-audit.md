**None critical.** The audit found no off-by-one, no repainting, no look-ahead and no unit inconsistency in the shipped engines; every property above was already enforced by construction and is now pinned by the new tests. ## 3) Gaps left open (documented, not fixed by 42-S3)

- **GAP-1 (hardening, non-critical):** the SCALPER core's H1/H4 context read (`readHtfTrend`, `src/lib/signal/scalper/core.ts:120-141`) uses the last bar of the supplied window directly; the forming-candle gate (`gateTfWindow:273-297`) is applied only to the M15/M5/M1 execution windows. The BASELINE core filters HTF bars internally (`causalTrendAt` `core.ts:142`), the scalper core does not — it relies on its loaders (`loadAnalysisInput` `src/lib/analysis/persistence.ts:50-57` — `isForming: false` only; `scripts/backtest-scalper.ts:159-169` `windowAt` — close-time filter). Both current callers therefore feed closed bars only: **no look-ahead is reachable today**. Recommended (engine owner, not 42-S3): add the same internal `close <= now` defense-in-depth filter to `readHtfTrend`.
- **GAP-2 (data, non-critical):** per-candle historical spread is not stored (documented in `src/lib/backtest/cost-model.ts:11-14`); the spread gate in backtests uses the observed baseline, so a real wide-spread environment would produce FEWER signals than simulated — the conservative direction, but it is an assumption, labeled everywhere.
- **GAP-3 (scope):** the M5-confirmation / M1-entry-timing rungs of the literal hierarchy in the master prompt exist only inside the scalper's OR-logic (M5/M1 judged independently, `scalper/core.ts:641-704`) and the M1 backtest harness (`scripts/backtest-scalper.ts` — `nowUtcSec` at M1 closes). The baseline engine is deliberately single-setup-TF (M15). Changing that is a strategy-version change, not an audit fix.
