PHASE 4 — SIGNAL ENGINE AND TIMING CORRECTNESS

Audit the complete signal path from source data to user-visible signal.

4.1 Establish the exact event timeline

2. Candle closure.

4. Strategy evaluation start.
5. Strategy evaluation completion.
6. Signal creation.

Measure:

- Decision latency: signal creation minus decision-candle close.
- Processing latency: evaluation completion minus evaluation start.
- Delivery latency: frontend receipt minus API publication.
- End-to-end latency: frontend receipt minus decision-candle close.

Record distributions, sample sizes, median, p95, and p99 where enough observations exist.

Do not invent latency results when no production or paper-forward observations exist.

4.2 Signal lifecycle rules

Implement and test deterministic handling of:

- Candidate.
- Confirmed.
- Issued.
- Expired.
- Cancelled.
- Invalidated.
- Outcome recorded.

Prevent duplicate signals for the same logical setup.

Ensure expired, invalidated, or stale setups cannot reappear as new actionable signals without genuinely new qualifying evidence.

Define signal validity using the strategy's actual rules, not arbitrary hardcoded assumptions.

4.3 Closed-candle discipline

A confirmed signal must not use future information.

If a strategy deliberately emits a provisional signal while a candle is forming:

- Label it "PROVISIONAL".
- Identify the forming candle.
- Never present it as confirmed.
- Define how it can be invalidated or confirmed.

For confirmed signals, use only information available at the decision time.

Ensure that signal creation, candle close, entry-zone validity, and expiry are consistent.

4.4 Late-entry protection

A signal must not be treated as actionable when:

- Its source data is stale.
- Its entry zone has already been invalidated.
- The market has moved beyond the permitted entry conditions.
- Its validity period has expired.
- Required timeframes lack valid data.
- Spread or volatility exceeds the strategy's tested limits.

Return a clear state such as "STALE", "EXPIRED", "INVALIDATED", or "NO_SIGNAL" instead of silently reusing an old setup.

Acceptance criteria

- No look-ahead leakage.
- No duplicate logical setups.
- No confirmed signal from invalid or stale data.
- Late signals are correctly rejected or marked non-actionable.
- Every signal can be traced to its source candles and strategy version.

5.2 Chronological research design

Use chronological splits. Never randomly shuffle financial time-series observations.

- Earlier 60%: development.
- Next 20%: validation and limited parameter selection.
- Final 20%: untouched out-of-sample evaluation.

Adapt the split only when justified by the amount of usable data. Document any change before examining the final OOS results.

Where data volume permits, run walk-forward validation across multiple chronological windows.

Prevent information leakage through:

- Future candles.
- Indicator warm-up.
- Overlapping labels.
- Shared setup outcomes across splits.
- Repeated parameter tuning on the final OOS segment.

The final OOS segment must not become a tuning dataset.

5.3 Execution assumptions

The application is READ-ONLY. Backtest fills are simulations, not real orders.

Model execution conservatively:

- Signal at candle close.
- Entry at the next eligible bar or a more accurate historical quote if available.
- Bid/ask directionality.
- Spread.
- Slippage.
- Commission if applicable.
- Stop-loss and take-profit collision rules.
- Entry-bar ambiguity.
- Session closures and gaps.
- Expiry and invalidation.
- Rejected or unavailable entries.

If historical spread is unavailable, label the cost as an assumption. Run sensitivity scenarios rather than presenting a current spread observation as historical truth.

If tick-level execution data is unavailable, disclose the limitations of candle-based fills.

Do not calculate monetary profit from unverified contract size, tick value, lot size, or currency conversion assumptions.

Keep results in R-multiples or price units when monetary conversion cannot be verified.
